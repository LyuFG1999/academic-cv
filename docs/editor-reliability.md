# 内容编辑与可靠性复查

## 编辑位置

后台按前台栏目顺序排列：个人资料与首页、研究与项目、研究成果、课程、博客、履历、高级设置。

- 基础资料：共用头像、双语姓名、职称、机构、简介、作者名与联系方式。
- 研究成果：论文与书籍、三个独立分类开关、引文导入。
- 履历：教育和工作经历，以及双语 Markdown 正文。正文的 `#` 标题与经历标题同级；成果保留在论文栏目，不在履历重复显示。旧技能字段保留在数据中，不自动转写为正文。
- 高级设置：导航开关和双语名称、配色、开场动画、维护、SEO 与域名说明。

## 博客为何没有出现在网站

“保存本地草稿”“提交仓库”“部署上线”“文章公开”是不同状态。新文章默认草稿，避免意外公开。在博客编辑器中将文章状态设为“公开”，再点击顶部“发布修改”，等待网站版本确认。中文文章显示在中文博客列表，英文同理。

后台会显示文章的草稿/公开状态。部署时可读取 Actions 状态则区分排队、运行、失败与等待 CDN；权限不足时回退为线上版本检测，不要求扩大登录授权。最长检查十分钟，超时只表示尚未确认，不等于发布失败。

预览按钮展示当前未提交正文、暂存图片和文末附件。预览采用无脚本、无同源权限的隔离 iframe，Markdown 过滤可执行 HTML 与危险 URL，链接仅展示。编辑后点击刷新预览。预览用于检查内容与排版，不承诺与网站自定义配色或代码高亮完全一致。

## 引文摘要

传统 BibTeX 强制模式会丢弃扩展字段。现在使用兼容 BibTeX 的 BibLaTeX 解析保留摘要，并支持 RIS 的摘要字段。重新导入同一成果可勾选补全空摘要，不重复创建，也不覆盖已有中英文摘要；缺失的原始摘要不自动编造。DOI 字段中的普通网址不会再拼成错误 DOI 链接。

## 维护与缓存

使用完整文档导航，站内页面链接携带构建版本。页面打开、从历史恢复、标签页重新显示以及可见时每三十秒检查部署版本；发现版本不同会尝试切到最新文档，每版本每路径最多恢复一次，避免 CDN 更新期间循环刷新。维护页的语言切换仅更新当前维护文档。

维护模式须部署完成才生效，不是实时访问鉴权，不能撤回浏览器历史缓存、已下载文件或公开 Git 历史。

## 审计采纳与保留项

已修复 RSS 日期字符串排序、根路径 `/` 归一化、sitemap 收录无语言中转页、重复首页 H1、外链行为不一致、字段定义缺失时错误不清晰。配色按钮文字根据背景亮度选择黑或白。测试入口使用 tsx，并在部署前执行，失败不发布。

兼容范围内更新依赖后，审计由 16 项减少到 4 项（2 high、2 low）；剩余涉及 Astro、sharp、esbuild 及集成依赖链，需要单独验证 Astro 跨大版本迁移，不代表已经消除全部安全风险。

未自动修改用户测试资料、公开草稿、删除上传文件、重写 Git 历史或改变 OAuth 服务架构。关闭导航只隐藏入口，不作为访问控制。Netlify 的忽略构建配置仍保留，避免意外重启旧站部署。

说明统一使用 `example.com`，真实域名只留在必要运行配置与实际站点地址中。替换当前文档不会删除旧提交中的历史内容。

GitHub 授权边界是 origin 而非 URL 路径；浏览器内存中的写令牌仍依赖同源脚本安全。当前没有把令牌改成 Worker 端会话，也没有擅自新建独立后台域名。上传文件进入公开仓库或部署后可能被访问，即使文章仍是草稿；删除列表项无法清除历史。请勿上传敏感文件。

## 验证

- 单元测试覆盖摘要保留与补全、RIS、Markdown 过滤、标题层级、资源路径、ZIP 导入、发布冲突和 OAuth。
- 浏览器验证五种前台屏幕尺寸，后台七个面板、隐藏字段验证、本地草稿恢复、图片/文件操作和一次提交。
- 独立根域名构建验证 CV 正文标题、RSS 顺序、sitemap；维护构建验证三种宽度、双语不跳出维护页，以及旧维护履历文档恢复为当前正常版本。
- 测试仅使用隔离数据，测试结束恢复原文件；不向线上提交测试文章。
